# 02 · 检测供应链系统

> 一家第三方检测机构的两块业务：两级分销的账，和一份样本从收样到出报告的全程。

**一句话：** 把「谁卖了多少、该给谁结多少」和「这份样本现在在哪一步」这两个问题，从微信和 Excel 里搬到一套系统里。

---

## 问题

检测行业的分销和普通商品不一样：
- 分销是**记账**不是发货——两级代理，货不走平台，钱要走账期；
- 报告不是文件，是**样本的旅程**：收样、编号、前处理、上机、复核、出报告，任何一步卡住，客户就在打电话催。

两块业务在两个世界里，对不上账是常态。

## 做法

**只做两块，别的一概不碰。**
两级分销（只记账）+ 检测报告（样本全链路）。业务边界写死在 README 第二行，因为边界一松，需求就会漫。

**接口先定契约。**
`docs/API.md` 是唯一事实来源，改接口先改它，再改两端。这条规矩救过整个交付期——前端和后端各自并行，没有一次因为字段名对不上卡住。

**交付物比代码重要。**
`docs/` 里是：需求 → 需求规格 → 六天作战计划（每天一个任务包）→ 决赛演示动线 + 录屏脚本 → 交付执行书 + 分工书 + 项目总结。
比赛现场讲什么、谁讲、第几分钟切哪个页面，都是提前写好的。
