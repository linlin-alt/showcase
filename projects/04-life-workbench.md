# 04 · 人生工作台

> 生活里散落的东西——记账、日记、身体数据、人际往来、机会、待办——最后都变成抽屉里的纸片。

**一句话：** 一个单文件网页应用。打一句话，系统自己判断这句话该归到哪几个地方，存成本地结构化数据。手机加到主屏就是 App。

---

## 问题

不是「没有工具」，是**工具太多**：记账一个 App、日记一个、体重一个、人脉一个。每个都要单独打开、单独记，最后全断更。

断更的真正原因：**录入的那一下太麻烦。** 想记「中午和朋友吃鸡煲花了 88」，得先选模块、选分类、填三个字段。

## 做法

**输入只要一句话，剩下交给识别。**
打「中午和朋友吃鸡煲花了 88」，系统判断这是餐饮支出 + 人际事件 + 地点，分别归档到三个地方。图片先本地识别再归档，语音同理。

**一个 HTML 文件，数据在本地。**
没有服务器、没有登录、没有云端。数据在你自己机器上，导出就是 JSON 备份。
线上那个版本是**只读快照**：禁写、不上云、改了什么只进浏览器缓存，换设备就没了——所以干脆把写入口禁掉。

**模块按「生活里真实存在的东西」切，不按功能切。**
纸条 / 日记 / 人际 / 身体 / 饮食 / 物资 / 资产收支 / 保险 / 机会 / 待办 / 菜单 / 命令。
「物资管理」管的是采购物品的存量和保质期——这个模块是过日子才想得出来的，做产品想不出来。

**联动，而不是并列。**
记一顿饭 → 自动记餐饮支出 + 关联到当天日记 + 如果提到店名，进地点候选。
一个动作写三个地方，你只需要做一次。

## 分层

```
┌─────────────────────────────────────────────┐
│  视图层   十几个模块视图，同一个 DOM 渲染管线      │
├─────────────────────────────────────────────┤
│  归档层   一句话 → 类型判定 → 拆成多条记录        │
│           本地 OCR（图片）· 语音转写 · 实体抽取   │
├─────────────────────────────────────────────┤
│  数据层   一个扁平集合树，十几个 collection      │
│           localStorage · JSON 导入导出 · 备份   │
└─────────────────────────────────────────────┘
```

## 三条设计规矩

1. **数据不出本机。** 没有一行代码会往外部发数据，图片和文字都只在浏览器里处理。线上版只读，是这条规矩的延伸。
2. **一个动作只做一次。** 任何需要用户填两个以上字段的操作，都算设计没做完。
3. **模块之间必须联动。** 孤立存着的模块，等于没做——记了饭不体现到支出，那记账还是得再做一遍。

## 我的角色

独立完成：需求、数据模型、全部实现、长期自用迭代。

## 技术

- 单文件 PWA（HTML + 原生 JS），无框架、无构建、无依赖
- localStorage + JSON 导入导出 + 定时备份
- 本地 OCR、正则实体抽取（店名、金额、时间）
- 浏览器内完成全部处理

## 现状

自己每天在用，连续两个多月没有断。数据量级上千条，分布在十几个集合里。

**这个项目真正的价值不是代码。**它证明了一件事：一个人不写代码，也能把一件自己忍了很久的事，做成每天真的在用的系统。
