03 · 照片工坊

一万张照片在手机里是一团乱麻。归完之后是 900 多个能一眼找到的文件夹。

一句话： 按拍摄地点把照片自动归进「日期\_时间\_城市区街道」的文件夹，每个地点精选几张代表作，顺手产出小红书 / 大众点评 / 抖音三套文案。

问题

出去玩一趟回来，相册多出几百张图。想发一条小红书，得手动翻四十分钟。 想找"那次在白云山拍的日落"，只能靠滑。

现有工具要么只按日期分（等于没分），要么把照片全传上去做云端识别（隐私 + 花钱 + 传一万张要一整天）。

关键取舍：重活放本地，AI 只干一次轻活

这是这个项目唯一重要的决定。

步骤在哪跑成本
步骤在哪跑成本
扫描 EXIF、按定位分类、聚类、精选、去重你自己的电脑0 元，一次性
看图写文案模型调用次数 = 地点数，不是照片数

一万张照片，AI 只被调用几百次。这条线划对了，成本从"不敢用"变成"一顿饭钱"。

做法

  • 文件夹名自带信息量：日期_时间_城市区街道，不打开就知道是哪次、在哪
  • 每个地点只精选几张：选图按清晰度、人脸、构图打分，不让你在 900 个文件夹里重新挑
  • 文案按平台分：小红书要标题和标签，点评要打分维度，抖音要前三句钩子
  • 演练模式：不想碰自己照片的人，双击「演练」用内置样片先跑一遍

我的角色

独立完成：需求、脚本、打包、文档、发布。

技术

  • Python 本地批处理（EXIF / 定位解析 / 图像打分 / 相似去重）
  • 打包成双击即用的 .command，首次运行自动准备环境，非技术用户也能用
  • 产出物：归档目录 + 每地点的九图 + 文案 markdown + 一份案例复盘网页

现状

  • GitHub Release 提供 photo-studio-v1.0.zip（1.1 MB，傻瓜包）
  • 文档按"你是谁"分流：只想整理照片看 5 分钟上手指南；报错看症状对照表；想改口径看进阶；想复刻看 SKILL.md（那是踩坑记录，不是功能列表）

实际跑过的量

9,544 张照片 → 900 多个文件夹，一次跑完。
